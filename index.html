Overview

なにをつくったか

ClayMonsters は「創る・育てる・戦う」を一本の体験にまとめた
Windows / Steam 向けゲームです。 開発期間は約4か月の個人製作です。 見た目の作り込みだけでなく、コンテンツパイプライン・対戦ドメイン・
ネットコード・Steam出荷までを自分で設計・実装しています。

エンジンは Unity 6（URP）。シーン単位の DI（VContainer）、MVP、
UniTask / R3 による非同期・リアクティブ設計を軸にしています。 編集 → 保存（glTF） → 育成 → 戦闘 → Workshop投稿の流れを サービス境界で整理しています。

Gameplay

プレイヤー体験

メニューから辿れる主要な遊びの柱です。

01

クレイエディット

スカルプト / ペイント / アニメーション。
GPU Compute と Jobs/Burst によるボクセル処理、
Marching Cubes によるメッシュ化、自動リギングまでを内製。

02

育成

日次ループ・天候・モチベーション・ショップ・技習得。
オート育成や訓練済みスロット保存など、
育成シミュレーションとしての厚みを実装。

03

リアルタイム戦闘

距離（間合い）・コスト・射程帯・カウンター・
部位破壊/復旧・ノックバック・チェーン。
CPU戦トーナメントと対人戦の両方に同じ戦闘ドメインを接続。

04

オンラインPvP

Unity Authentication / Lobby / Relay + Netcode for GameObjects。
ロビーからアリーナまでのマッチメイキングと入力同期を実装。

05

展示室 & デスクトップペット

Steam Workshop への投稿・閲覧・お気に入り。
本編終了後は別プロセスのデスクトップペットへ引き継ぎ、
Steamプレイ時間を継続するランチャー設計。

Engineering

就職活動で伝えたい技術点

「ゲームを一本作った」だけでなく、
設計判断と実装の深さで評価してもらうためのポイントです。

  • 内製ボクセル粘土パイプライン GPU / CPU 両バックエンド、Marching Cubes、自動リギング、
    部位欠損、glTF へのスキン付きエクスポートまでを一本化。
  • 複雑なリアルタイム戦闘ドメイン 間合い・コスト・射程・部位・カウンターをドメインモデルとして整理し、
    Presenter 経由で UI に R3 でバインド。
  • オンライン対戦の実装経験 Auth → Lobby → Relay → NGO の接続経路、
    マッチメイキングサービス、入力リレーを分離して実装。
  • Steam出荷を見据えたプロセス設計 Launcher / 本編 / Desktop Pet の三プロセス構成。
    プレイ時間継続と Workshop UGC まで含めたプロダクトとしての完成度。
  • 保守しやすい UI / DI 方針 シーン単位 LifetimeScope、MVP、SerializeField 手動配線を正とし、
    実行時の Find / レイアウト書き換えに頼らない設計ルールを運用。
  • 多言語・セーブ保護 TSV テキストテーブルによる 9 言語対応。
    セーブデータの保護（HMAC 等）も実装。

Architecture

アーキテクチャの骨格

Bootstrap → Title
（ルート LifetimeScope）
ClayEdit / Training / BattleNpc / BattlePvpArena
（シーン Scope + MVP）
BattleSystem ドメイン ← R3 → Presenter → View
（Canvas.enabled で表示制御）
Save / glTF / Workshop / Netcode は
Service 境界で接続

UI の RectTransform や Hierarchy は Prefab / シーン配置を唯一の正とし、
実行時生成やレイアウト補正に依存しない方針です。 「動くデモ」ではなく「長く直せる構造」を意識しています。
